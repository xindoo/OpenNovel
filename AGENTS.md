## CONVENTIONS
- **Snake_case in DB/API** vs **camelCase in frontend**: DB columns are snake_case, API responses keep snake_case, frontend code uses camelCase. No transformation layer — frontend reads snake_case directly from API.
- **Timestamps**: D1 stores as `datetime('now')` (ISO string), API converts to Unix seconds (`getTime()/1000`) before returning.
- **Category format**: Comma-separated string (both `,` and `，` supported), not a separate table.
- **R2 key pattern**: `novels/{id}/covers/{uuid}.{ext}` for covers, `novels/{id}/chapters/{filename}` for chapter content.
- **Frontend imports backend types** via relative path `../../src/types` — no build isolation between frontend/backend.
- **No tests**: No test framework configured, no test files found.

## ANTI-PATTERNS (THIS PROJECT)
- Do NOT add JWT/session auth — project uses Basic Auth intentionally (admin-only, no user accounts).
- Do NOT add a separate API server — everything runs on Cloudflare Workers via `wrangler`.
- Do NOT use `node:` imports — Workers runtime uses `nodejs_compat` flag, prefer Web APIs.
- Do NOT modify `frontend/dist/` directly — it's generated by `vite build` and served as static assets.

## UNIQUE STYLES
- **Admin auth**: Basic Auth with constant-time comparison (timing-safe), credentials from env vars.
- **Reader pattern**: Full-screen overlay via `ReaderContext` (not a route), triggered from any page.
- **SPA + Workers**: Frontend built separately, served as Workers Assets with `run_worker_first = ["/api/**"]` — API routes hit Worker, everything else serves SPA.
- **Chapter content in R2**: Only metadata in D1, content stored as markdown/text in R2, fetched on demand.

## COMMANDS

```bash
npm run build        # wrangler deploy --dry-run
npm run deploy       # wrangler deploy to production

# Frontend (Vite)
cd frontend && npm run dev     # Vite dev server
cd frontend && npm run build   # tsc + vite build → frontend/dist/

# D1 Migrations
wrangler d1 migrations apply opennovel-db --local    # Local
wrangler d1 migrations apply opennovel-db --remote   # Production
```
